# 对话驱动状态闭环

这份说明记录自由交谈影响游戏状态时采用的执行原则。人物模型只负责表达人物意图和候选提案；GM 负责确认目标、可用路径和价值；Mod 执行器负责调用已接通的原版入口；最后必须读回状态并刷新玩家可见界面。

## 当前闭环

1. 进入对话时捕获原版人物、交易物品、库存归属和世界修订号。
2. 人物模型生成自然回复和结构化候选提案。
3. 涉及交易、补付、回访、找货、交换或持续世界变化时，GM 使用同一份上下文复核。
4. 执行前再次检查当前人物、物品唯一标识、归属、价值、预算和目标路径。
5. 只调用目录中状态为 `implemented` 且有执行器的能力。
6. 原版写入后读回结果；报价修正会刷新当前原版报价界面，混合交换补付仍等待原版接受。
7. 执行结果写入世界事实。后续人物只能看到公开事实，或明确涉及自己的事实；不会读取其他人物的私密对话。

## 路径选择

目标路径目录同时保存“已发现”和“可执行”两种状态。发现 `PlayerStore` 或警报器字段不等于 Mod 已经拥有安全写入点。未接通的路径会在执行前拒绝，人物不会收到“已经生效”的反馈。

目前可以执行的世界修正是 `price_modifier`、`demand_modifier` 和 `supply_modifier`。偷窃判定、警报器阻止率、保险覆盖等仍需先完成真实读写和验证，不能用字段名替代接口。

## 事实反馈

交换、随身货物展示、议价、预算补付和 GM 世界修正都会生成事实记录。记录不直接替代原版状态：它只是为下一轮人物对话提供已经发生的结果。跨天事件和公共经济变化继续走新闻投影；私人议价和个人交易不会自动登报。

## 后续扩展

- 为每个原版能力补齐统一的执行回执、失败原因和可选补偿动作。
- 为偷窃、警报器和保险路径增加真实读写点、读回验证与到期恢复。
- 将成交、失窃、回访到店和委托失败接入同一事实流，并为公开事件设置冷却和去重。
