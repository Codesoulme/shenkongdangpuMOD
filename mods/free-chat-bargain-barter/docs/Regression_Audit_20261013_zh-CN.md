# 0.2.1 回归检查记录

日期：2026-10-13。目标游戏：Probably Stolen Demo 0.46D。

## 本轮发现并修复

1. 回复迟到时，原代码先写人物和世界状态，后判断对话对象是否变化。现在先核对窗口与人物；顾客离店或电话明确挂断会关闭对应待回复会话。
2. 人物说“不行”“答应不了”或“可以考虑一下”时，结构化提案可能仍标为接受。现在明确拒绝会取消本回合可执行提案；“我不想走，但可以换”仍可被识别为交易同意。
3. 缺少待补付记录时，交换结算曾把它报告为成功。现在普通交换不会误取旧补款；混合交换在接受报价前重新确认补款记录、金额、人物和预算。

## 仍需实机验收

- 电话连续多轮交谈、挂断与重拨，确认输入框不会过早关闭或承接旧回复。
- 顾客离店后同一人物再次来店，确认旧回复不会写入新一轮关系、承诺或交易。
- 混合交换提议后先改变顾客预算，再点“接受报价”；应拒绝不完整成交。正常接受后，物品与信用点应一同到位。
- 多件交换、顾客临时随身物、报纸布局、价格恢复，以及剧情来客与回访队列并存。
- 偷窃、警报器和保险目前只有安全状态读取探针，尚无经过验证的可写原版落点。

本轮未启动游戏，未将上述实机项目记为通过。
